Live Android logcat capture / 32-second walkthrough

Record Android logs and screen video in the same session.

See a connected device stream logcat beside its live screen, mark an issue with a screenshot, and save a snapshot while capture continues.

THE WRITTEN WALKTHROUGH

  1. Connect a device. Choose an authorized USB device or pair an Android 11+ phone using wireless debugging.
  2. Start capture. Indagium streams logcat and, by default, records screen video with an embedded live mirror.
  3. Investigate live. Filter, search, and inspect new rows while reproducing the issue on the device.
  4. Mark the moment. Use Mark issue to save a time-bounded log marker and, when available, a screenshot; add a note in Notes.
  5. Save a snapshot. Export a ZIP by default or choose Indagium Compact (.ind) without stopping the live capture, then reopen the archive to review its log and video in sync.

From connection to evidence

A repeatable Android capture workflow.

01

Connect by USB or Wi-Fi

Use an authorized USB debugging connection, or pair on Android 11+ with Wireless debugging by QR code or pairing code. Indagium uses installed Android platform-tools (adb).

02

Capture logcat and the screen

Log streaming starts with the session; screen video recording is on by default. The live device mirror is embedded in the capture workspace. A host scrcpy installation is only needed if you choose its separate external mirror window.

03

Analyze while reproducing

Use Indagium's normal log viewer, filters, search, highlighters, and Notes while new rows arrive. Mark issue records a log time window and can take a screenshot for context.

04

Review synchronized logs and video

Open the saved ZIP or Compact archive in Indagium. Synchronization metadata links the included log and available video, so log rows and video seek together without a manual attachment step.

Reboots and temporary disconnects / one continuous session

Keep the capture running while the device restarts.

When the selected device goes offline, the capture remains active and shows Waiting for device. Indagium retries logcat and screen recording for that original authorized ADB connection until the device returns or you stop capture.

01 · WAIT

Keep one session on the original device

Start a normal capture, then leave it running when the phone or emulator restarts. Waiting for device clears when the original authorized ADB connection returns. If wireless debugging returns at a different address or serial, reconnect the original endpoint or start a new capture.

02 · REVIEW

Inspect device events and reboot evidence

Open Device events in the capture bar or Issues → Device events in a shared ZIP to review each interval's downtime and reboot evidence. A reboot is confirmed only when boot identity is available before and after the outage. If log markers are disabled, the event remains available but its marker-row jump is not.

03 · RESUME

Continue with the device's logging choices

After a verified restart, Indagium restores saved buffer sizes, the global log level, and per-tag overrides when Android permits it. Successful changes through Indagium update the values. Indagium checks settings again after boot and reports when Android denies a change. It does not automatically restart ADB as root. With earlier logs enabled, repeated Quick Boot rows are deduplicated while genuine early-boot rows from a confirmed new boot are retained.

04 · SHARE

Save the interval from a snapshot

Use Save snapshot during capture or after Stop. From a reopened capture archive, choose Export → Export capture range…, then set a range or use the video playhead. The exported archive contains captured logs and can include optional video, notes, markers, screenshots, and synchronization metadata.

For planned restarts in automated tests, AI test runs can call wait_for_device_ready to wait for authorized ADB and completed boot while lane capture recovers.

Choose your connection

USB logcat capture or wireless logcat.

Both connection methods use adb from Android platform-tools. Install platform-tools on the computer and select its adb executable in Capture Settings if it is not already on PATH.

USB: enable Developer options and USB debugging on the Android device, connect its cable, and accept the computer's authorization prompt. The New capture launcher shows whether adb sees the device and whether it is authorized.

Wireless: on Android 11 or later, enable Wireless debugging in Developer options while the computer and phone are on a reachable network. In Indagium choose the pairing option shown for the device and scan the QR code or enter the pairing code from Android's Wireless debugging screen. If network discovery is blocked, enter the address and code manually.

The host scrcpy application is optional. Indagium's default embedded mirror and video recorder use its bundled device-side server over adb; install host scrcpy only to open the distinct external mirror window.

Snapshots and saved sessions

Save a capture archive during capture or after Stop.

Save snapshot exports a point-in-time selection while capture continues or after it has stopped. Choose all available history, a recent time range, rows since the last successful snapshot, or the interval between selected capture rows. ZIP is selected by default for broader tool compatibility; choose Indagium Compact (.ind) for a smaller archive opened in Indagium. Compact losslessly compresses the log and may convert video to lossy AV1, which can take extra time and working space; it copies existing AV1 and keeps the original if conversion is unavailable or would not make the video smaller. The zstd compression library is included in Indagium; no separate installation is needed. Video is optional; Indagium reports its actual coverage when it starts later or ends before the logs. See the ZIP and Compact format details →

SNAPSHOT

Export while recording or after Stop

Use Save snapshot from a live or stopped capture. Choose the log range and format, then include video, screenshots, marker details, and notes where available. ZIP is the default; select Compact for an Indagium archive. Saving does not end a live capture.

RANGE

Cut a range from a reopened archive

After opening a capture ZIP or Compact archive, choose Export → Export capture range… above the log. Use the current video playhead, choose a preset range, or enter exact start and end times for an archive export. The source archive stays unchanged.

SYNC

Reopen an archive to investigate

Open the capture ZIP or Compact archive in Indagium. It verifies the included files, loads the log, and links the available video automatically. Select a log row to seek video, or move the video to inspect the corresponding log time.

RECOVERY

Recover an interrupted session

If Indagium closes before Stop, the recorder cannot resume the device stream after restart. The New capture launcher lists the retained interrupted session so you can open its available log/video data and save what was captured.

Settings and compatibility

Choose how much to capture.

Recording choices such as video, audio, microphone, and video limits are saved for the next capture. During a live session, changes to device log buffers and levels made in the Device logging panel apply to the device and update the values restored after a verified reboot when Android permits. Mirror interaction and live playback controls remain available separately.

  1. 01

    Earlier log buffers are optional

    By default, logcat streaming begins when you start the capture; earlier device buffer contents are excluded. Turn on the option to include earlier buffered logs if you need events from before reproduction began. Video recording is on by default. Audio recording is off by default.

  2. 02

    Audio and microphone are opt-in

    Capture audio requires Android 11+ and records supported device playback; apps can block it. While it is captured, the phone speaker is muted by default. On Android 13+, enable Keep sound on the device to request playback through the phone speaker too; older devices cannot honor that option. Audio in an exported capture is retained in MKV. The embedded mirror's live playback on the computer is a separate speaker toggle and starts muted. A computer microphone is another separate input, off by default.

  3. 03

    Timing may need calibration

    Indagium estimates the initial relation between log and video time and can apply a manual millisecond offset. Capture archives store synchronization metadata for the recorded timeline. When video starts late, reconnects, or does not cover the whole selected log range, Indagium reports that coverage rather than claiming full overlap.

  4. 04

    Storage limits protect the session

    Capture settings include a session size limit and a minimum free-space reserve. Choose separate folders for retained sessions, snapshots, and saved ZIP archives in Settings. On older Linux systems without the required glibc/native media support, video recording and the in-app mirror are unavailable; log capture continues, with an optional host scrcpy window when installed.

  5. 05

    Set how device outages appear

    At Settings → Capture → Device availability, Write device availability markers to the log and Show unavailable device periods in playback and exported video are enabled by default for new captures. The full elapsed interval is preserved; with the playback option enabled, playback or exported video shows a Device unavailable card.

Questions

Android logcat capture, answered.

Can Indagium record Android logs and screen video together?

Yes. Start a device capture to stream logcat and record the screen in the same session. Screen video is on by default and can be turned off in Capture Settings.

Can I capture over USB and Wi-Fi?

Yes. Connect an authorized USB-debugging device, or use Android 11+ Wireless debugging and pair by QR code or pairing code. Both routes require Android platform-tools with adb installed on the computer.

Do I need to install scrcpy on my computer?

Usually no. The default embedded mirror and screen recording use Indagium's bundled device-side scrcpy server. Install host scrcpy only if you want the separate external mirror window.

Does Save snapshot stop a live capture?

No. Save snapshot exports a point-in-time archive while log and video recording continue; ZIP is the default, with Indagium Compact (.ind) as an option. Stop ends and finalizes the session; Save ZIP or Save Compact exports the retained session afterward.

Will the log and video synchronize when I reopen a capture archive?

Yes. The capture archive stores synchronization metadata and references the included log and video. Indagium verifies those files and automatically links available video when the ZIP or Compact archive is opened.

What happens to a live capture if the Android device reboots or disconnects?

The same capture remains active and shows Waiting for device while Indagium retries logcat and screen recording for the original authorized device. Recording resumes when that device returns. Stop ends the capture. If wireless debugging returns at a different address or serial, reconnect the original endpoint or start a new capture; Indagium does not guess a replacement.

What does Indagium record while the device is unavailable, and where can I review it?

The device log stream and new screen images pause while the device is offline. Availability timing and optional marker rows preserve the interval, and playback or exported video can show a Device unavailable card. Open Device events from the capture bar or choose Issues → Device events in a shared ZIP to review it. A reboot is confirmed only when boot identity is available both before and after the outage.

Will Android logging settings and earlier logs be restored after a reboot?

Indagium restores saved buffer sizes, the global log level, and per-tag overrides after a verified restart when Android permits it. Successful logging changes made through Indagium during capture update the values it restores; Indagium checks settings again after boot and reports when Android denies a change. It does not automatically restart ADB as root. With Include earlier device logs enabled, repeated buffered rows after Quick Boot are deduplicated while genuine early-boot rows from a confirmed new boot are retained.

Can I save a snapshot while the device is unavailable?

Yes. Use Save snapshot during capture or after Stop and choose ZIP or Compact. After reopening a capture ZIP or Compact archive, choose Export → Export capture range… and set a time range or use the video playhead where available. The archive contains captured logs and can include optional video, notes, markers, screenshots, and synchronization metadata.
