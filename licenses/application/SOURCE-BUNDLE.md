# Application and JVM source acquisition

For new official Indagium releases that ship the EULA, download `Indagium-<version>-application-sources.tar.gz`, its `.sha256` and `.manifest.json` from the **same release** as the installer at https://github.com/indagium/indagium/releases. Use the exact version, not `latest`, when retaining a source record. The complementary `Indagium-<version>-media-sources.tar.gz` covers FFmpeg and its native closure. Source downloads do not require EULA acceptance, an account with Indagium, or payment. These source archives retain upstream licences; they are not licensed under the binary EULA.

Downloadable CI packages must include both source archives, checksums and manifests. Published release sources must remain available at the release-specific public location; expiring CI storage alone is not sufficient. Earlier installers keep their original terms. This new release procedure does not assert that missing source assets for an older release have been supplied.

The installed `legal/source-acquisition.json` (in the app directory: `Contents/app/legal/` on macOS, `lib/app/legal/` on Linux, `app\legal\` on Windows) gives the exact version-specific HTTPS links for both archives, checksums and manifests. Their stable URL pattern is `https://github.com/indagium/indagium/releases/download/v<version>/Indagium-<version>-application-sources.tar.gz`, with `media-sources` for the complementary archive. Future release publication verifies that both sets have been uploaded before making the binaries public. Sources are also included directly with downloadable CI packages.

## Preparation and verification

Run `./gradlew prepareApplicationSources`. The task checks `application-source-lock.json` against the LGPL/CDDL modules in `gradle.lockfile`, downloads its HTTPS inputs, verifies every SHA-256, checks the complete JVM source tree and matching vendor build recipes, and creates the archive under `build/`. Run `sha256sum -c Indagium-<version>-application-sources.tar.gz.sha256` (or `shasum -a 256` on macOS). The manifest lists individual files, hashes, application version and the pinned runtime. A download or checksum failure prevents assembly.

The archive contains the unmodified Maven sources, POMs and binary evidence for LanguageTool, OpenRegex and selected CDDL Java EE components, full LanguageTool/OpenRegex project sources, English dictionary preferred source inputs and build scripts, the vendor's complete OpenJDK source archive including native HotSpot and build files, and the exact Temurin build-recipe revision and platform build metadata. It is not just Java's `src.zip`. The dictionary 0.6 artifact does not publish a sources JAR; the lock records the selected upstream source commit and its provenance explicitly. No byte-for-byte reproducibility claim is made.

For Java-library rebuilds, use the full project archives and their POM/build instructions; the published sources JARs and POMs provide additional versioned evidence. The English dictionary project includes the preferred text dictionaries and `build-dicts-from-src.sh`, `build-spelling-dicts.sh` and `build-tagger-dict.sh`; preserve all source-data notices. Build tooling and external dependencies may need to be installed as directed by upstream. The Temurin build metadata contains the platform configure and `makejdk-any-platform` arguments; use the bundled recipe revision and full source tree when rebuilding the matching JVM. The compiler/boot JDK and OS prerequisites remain platform-specific.

## Library replacement

Stop Indagium and copy the installed image first. LanguageTool and OpenRegex remain unmodified separate JARs in the application's JAR directory: macOS `<Indagium.app>/Contents/app/`, Windows `<install directory>/app/`, Linux `<install directory>/lib/app/`. Replace the relevant JAR with a compatible build, retaining the filename and public interfaces expected by the launcher and application. Retain applicable notices; preserve the other dependency JARs. Test proofreading after replacement. Compatible modifications, relinking and reverse engineering to debug those modifications remain permitted by the applicable LGPL, including modification of the combined work for your own use. No binary EULA prohibition overrides these rights.

For FFmpeg replacement and JavaCPP cache handling, see the media source instructions. Modifying an app bundle can invalidate a platform signature; copied applications may need signing as required by that platform. This is not a technical requirement to obtain the licensor's signature or approval before exercising LGPL rights. Redistribution of Indagium's own binaries and independently licensed third-party code follow their respective terms.

## JVM mapping

Official builds use the exact Temurin build in `application-source-lock.json`. `python3 scripts/prepare_application_sources.py --install-jdk --platform macos-arm64 --output-dir build/release-jdk` downloads and checks the pinned vendor JDK and prints its local home; use the appropriate platform name on other systems. Set `JAVA_HOME` to that home before starting Gradle. The source build remains available without this official-packaging restriction.

Each official installed image includes `legal/runtime-license-manifest.json` in its app directory (as above), recording its source JDK identity, module list, runtime release file and legal-file checksums, plus the runtime source mapping. The runtime itself retains its `legal/` notices. Package validation checks those records after extraction. JVM modifications remain governed by their upstream terms and the Classpath Exception; the EULA does not turn JVM sources into proprietary software.
