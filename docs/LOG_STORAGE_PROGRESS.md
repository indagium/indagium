# Log storage redesign: progress and remaining work

This branch is not a completed storage redesign. The application still opens logs through its existing eager storage path; there is no `LogStore` viewer route and no claim that the plan's memory or latency gates pass.

- Baseline: `codex/ram-poc` starts at `8a926501a1c3622423de9318e674a70afb580cfa` with uncommitted POC changes preserved. `scripts/ram-poc-manifest.py` records the tracked diff hash, selected POC untracked-file hashes, generated fixture hashes and JVM/machine identity. Its output is a snapshot of the worktree at the time it runs, not a reconstruction of earlier benchmark binaries.
- A1: focused close, pin, cache/cancellation and trim regressions passed. A controller creation/publication race was addressed, with deterministic tests for competing creation and late completion after tab close, video replacement/detach and shutdown. [Review and native attribution](LOG_STORAGE_A1_REVIEW.md) and [20-cycle screening](RAM_POC.md#twenty-cycle-video-screening-after-controller-ownership-fix) leave native-memory attribution unresolved. Lifecycle and projection edits still share files and have not been isolated as separate commits.
- A2: separate test-only metadata and timestamp candidates and a generated-data harness exist. Their shallow layouts, mixed-format memory tradeoffs and timestamp allocation costs are in [the compact experiment](LOG_STORAGE_COMPACT_EXPERIMENT.md). Both present prototypes are rejected for production; format-specific regressions or repeated-access allocations and missing real-view timing and compatibility evidence prevent acceptance.
- B: [a draft ADR](LOG_STORAGE_ADR_DRAFT.md) records leases, versions and semantic hazards. An internal experimental legacy in-memory adapter now exercises snapshot lifetimes, bounded pages, sparse IDs and cancellation; its focused tests pass. It retains all decoded rows and a boxed index, and does not implement queries, time lookup or viewer integration. The broader contract is not frozen.
- C–D: an experimental UTF-8 file index, bounded page reader, primitive query results, existing-filter adapter and backpressured page stream are implemented and have focused tests. They are not wired into the app. The reader rejects UTF-16, detects ordinary file changes through metadata, and caps concurrent scan/page builds; its record scratch space and index still grow with input. Preliminary model-only numbers in [RAM_POC.md](RAM_POC.md#experimental-indexed-source-screening) show slower indexed filtering.
- E–H: an experimental compact event projection shares the existing grouped traversal for eager-backed tabs, and separate paged stack and sequence scanners have focused parity tests. The shared-traversal projection still requires eager group preparation and a caller-held row lease. A separate experimental stack-only projection uses the paged scanners and filtered query; it explicitly rejects sequence and manual grouping. A generated-file pipeline test covers indexing, filtering, stack projection and bounded decoding, but it is not an application viewer test. Top-level query, stack and sequence scans now share a two-permit cancellable limit, while page builds have their own two-permit limit; group indexes and transient allocations still grow with input. Sequence/manual file-backed grouping, viewer integration, archive/capture adapters, full parity tests and acceptance runs are outstanding. A paged export prototype and compact selection expression exist but are not wired into the app; the export requires a caller-owned commit fence and a bounded primitive-ID resolver supports copy-like selection, but group expansion and application selection state remain unintegrated. No unsupported route has been promoted. Optional JVM and native-engine experiments are also outstanding.

Before promotion, complete the plan's independently reviewed contracts, real-view integration and support matrix; test cancellation, change detection, identity, grouping, selection, exports, restoration, appends and video alignment; and run the prescribed controlled application memory/latency matrix. Existing synthetic measurements do not establish the user-visible memory improvement.

The later experimental stack-only projection rejects sequence/manual modes and is covered by a generated-file pipeline test; it is not wired into the application. The export prototype requires a caller-owned generation commit fence. External file mutation cannot be made atomic with the metadata check, and cancellation racing a completed replacement can still report cancellation after commit.

The stack-only projection now combines the filtered query with unfiltered stack groups and rejects sequence/manual mode explicitly. A generated-file test exercises indexed reading, filtering, stack folding and bounded page decoding. This is still not the real viewer. Paged export now requires a caller-supplied synchronous generation commit fence; external rewrites that preserve checked metadata cannot be excluded. Focused storage, stack, sequence, grouping and export checks pass. The latest `ktlintCheck` and `detekt` run has only the pre-existing Seq3 findings; see `build/ram-poc/storage-rechecked.log`.

The generated-data filter benchmark was corrected to use a shared operation-local regex context. A short, separate JFR sample identified line scanning as a candidate; an experimental reusable line buffer passed boundary and oversized-record tests. Preliminary 1m results remain far slower than eager filtering and are not a promotion result; see [RAM_POC.md](RAM_POC.md#shared-regex-context-and-line-buffer-experiment).

An internal stack-only file session now composes source, query, unfiltered stack scan, projection, page-reader ownership, copy-selection resolution and fenced streaming export. It rejects enabled sequence/manual groups and timed-out filters, and uses caller-supplied process analysis; it is not routed from the app, does not implement view interactions, and is not the plan’s real-viewer milestone. The separate selection resolver sorts a primitive ID array for copy and cannot be interrupted during that sort; count limits bound IDs, not bytes.

Session operations are tracked as child jobs with a two-operation limit. Closing the session closes its export commit gate, cancels active and waiting operations without cancelling their callers' parent jobs, and releases its resources; `awaitClosed` waits for resource closure and the tracked jobs to drain. Callers must still fence page and clipboard publication. A non-cooperative operation can delay that wait. The focused operation test covers this case, and session tests exercise idempotent close and the completion wait.

An experimental projection viewport controller now requests bounded decoded pages off the caller's thread, rejects stale results and malformed page metadata, and owns session shutdown. This is a handoff for a future viewer integration; the current application does not instantiate it and it does not reduce application memory.

The subsequent storage-package run passed 87 tests across 21 suites. Repository-wide `ktlintCheck` and `detekt` still fail on the existing Seq3 findings, with no storage findings in that run. Raw output: `build/ram-poc/storage-session-rechecked.log`.

Grouped views for tabs with a source path and without active tailing now use an in-memory representation that retains entry references and style runs instead of a separate `LogItem.Row` per displayed entry. Stack toggles preserve that representation. This is an incremental change to the eager viewer, not the file-backed storage route; a subsequent append can convert it to the existing append-only item list. Grouping and append tests passed (132 tests), as did the tab-close lifetime tests. Repository checks still fail on the existing Seq3 findings; no new findings were reported for this change. Logs: `build/ram-poc/grouped-rows-rechecked.log` and `build/ram-poc/grouped-rows-lifetime.log`.

An additional parity run checked the compact path against the existing projection cases, including overlapping stack, manual and sequence groups (`build/ram-poc/grouped-rows-parity.log`).

One isolated forced-GC screen opened a generated one-million-row grouped archive in the real viewer and observed 259.2 MiB used heap while open and 22.5 MiB after close (`build/ram-poc/results/current-1m-archive-forcegc-pnx98x4e`). Earlier grouped screens observed 287.3 and 291.3 MiB while open, but used earlier builds and are not a controlled comparison. These observations do not prove the memory or latency acceptance gates; alternating runs against an equivalent baseline and broader grouping workloads remain necessary.

The indexed reader now uses a bounded reusable record buffer and batched input reads. Focused boundary tests passed after fixing an EOF bug found in the first test run. A three-launch generated 1m screen improved index/filter medians, but indexed filtering remains slower and has not passed the real-viewer timing gate; see [RAM_POC.md](RAM_POC.md#shared-regex-context-and-line-buffer-experiment).
