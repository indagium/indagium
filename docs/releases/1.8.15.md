# Indagium 1.8.15

Indagium 1.8.15 adds compact capture archives that are much smaller to store and share, and makes opened archives easier to re-export or unpack.

## Compact capture archives

Export a capture as a **Compact** archive: the log is compressed with zstd, the video can be re-encoded to AV1 (about 3x faster than before, with encode progress shown) or kept as the original, and synchronization anchors keep the log and video aligned with less metadata. Compact archives use the `.ind` extension, which Indagium now registers as a document type so double-clicking one opens it. Device codec selection is available when capturing.

Opened archives stay useful: saving a ZIP or Compact export of an opened archive exports that archive, and the export range popover can **Extract** an opened archive as plain files once its snapshot is linked. Repeated opens reuse earlier extractions, and the extraction cache is swept safely, including across multiple running instances.

## Reliability

- Capture sessions stay listed when their sync metadata is unreadable, and **Follow** remains available on imported v5 capture archives.
- Capture file handling is hardened for Windows and Linux, including move fallbacks and retries on Windows.
- Video seeking lands on the first frame when audio starts before the video.
- A corrupt zstd capture log is reported as an archive error rather than a crash.
- Export reports video coverage in the source session's local time, and no longer loses rows at export boundaries.
- The capture navigation index is built off the UI thread, so large captures no longer stall the interface.
- Notes no longer glide when switching tabs, because note Markdown is parsed synchronously and cached.
- When the global loading cover stays up unusually long, a diagnostic report is written to help track down the cause.
